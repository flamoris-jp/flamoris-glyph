# 「もういいよ」：三つの考え方を一つの歌詞へ

**Status: finite offline artwork prototype.** 比較のための新しい軸を増やす段階から、
既存の文字骨格を借り、骨格・DNA・ストロークを組み合わせて、実際の歌詞を描く段階へ進む。

| 入力 | この作品で担うもの |
|---|---|
| 骨格 | 点画の配置と全体の比率。open / tall / compact |
| DNA | 書法を含む共通の造形傾向。接触面の形・角度、入り、抜け、太さの膨らみを内包 |
| ストローク | その時の表情。傾き、線の反り、先の伸び、角の丸め、強弱、微小な上下変化 |

道具・書法を独立した第四・第五の入力にはしない。過去の単画用 `StrokeProgram`
（実行動作の記述）と、今回の `Stroke`（表情を与える入力）は用途が異なる。
旧APIやbundle-v2は変更していない。

## 歌詞と組み合わせ

`examples/mou-iiyo/lyrics.txt` に、各行で日本語と英語が混ざる10行の歌詞を保存した。
全作品で語句・大小文字・アポストロフィ・改行・全角空白を維持する。

- **TENDER**：open骨格 + ribbon DNA + gentleストローク。
- **SURGE**：tall骨格 + 同じribbon DNA + energeticストローク。
- **PLAYFUL**：compact骨格 + soft DNA + cuteストローク。

三作品は、作品として三入力を組み合わせたもの。色・骨格・DNA・ストロークの
個別効果を切り分ける実験ではない。別の `same-dna-strokes.svg` では、同じopen骨格、
ribbon DNA、色、配置を使い、ストロークだけを変えた「もういいよ It’s all right」を描く。

ストロークは輪郭全体を後から斜めにする処理だけではない。太さを付ける前の中心線に、
弧長に応じた反り、終端方向への伸び、局所的な角の平滑化を加える。DNAが、その経路に
楕円接触面・入り・抜け・膨らみを与える。重ねた接触面の和から閉じた輪郭を作る。
元から輪になっている字の内側は穴として残す。無効な形を修復して通す処理はない。

## 骨格を一から研究し直さない

日本語は **KanjiVG** の明示された点画経路を利用する。歌詞に必要な28文字・99画だけを、
commit `70a0b7ae0c18ceb5cb358274b029cce0234a43bc` から抽出した。元の点画経路は
`kanjivg-subset.json` に保持し、輪郭フォントからの自動骨格抽出とは扱わない。
英字30文字と曲線アポストロフィは手で作成したオリジナルの中心線。
同じ描画処理で日本語・英字を描き、一行の中に並べる。

KanjiVGはUlrich Apel著、**CC BY-SA 3.0**。本作品の日本語派生グリフ・ポスター・
プレビューは同ライセンスを適用し、出典・変更・リンクを `ATTRIBUTION.md` に同梱する。
Latin入力とPythonコードはApache-2.0。第三者の骨格データとコードのライセンスを区別する。
詳細は [作品の出典](../examples/mou-iiyo/ATTRIBUTION.md)。

## 再現

```bash
python -m pip install -e ".[patterns]"
python -m flamoris_glyph.lyric_performance examples/mou-iiyo --out output-lyric-performance
python -m flamoris_glyph.lyric_performance examples/mou-iiyo --intensity 4 --out output-lyric-exaggerated
python -m unittest discover -s tests -v
```

### ストロークの感情を強める

`--intensity` は **1〜4の有限数**。ストローク内部の表情の度合いであり、
第四の設計層や、計測された「感情の何倍」という値ではない。既定の1は初回の
177個のグリフSVGとbyte単位で同じ形状を維持する。

強めた場合も骨格とDNAの入力は固定する。反り・傾き・先の伸び・局所的な丸め・
押し引きに加え、ストロークの広がりや縦の収まりを連動させる。可愛い表情は
横にふっくら、勢いは強い反りと鋭い伸びへ寄せる。既存DNAの接触面・書法は維持する。

強い変形では、元の明示経路どうしの交点付近で局所変形を弱め、横棒と縦棒が
離れることを抑える。閉じた経路では追加の終端伸ばしを抑える。8画以上の密な字は
追加の押し・強弱の増分を35%にし、小さい空間が太さだけで埋まることを抑える。
これは字形の美しさ・全交点の一致・可読性の自動保証ではない。範囲外の形状は
従来どおり拒否し、切り抜きや自動縮小で隠さない。

1より大きい値では `before-after.svg` も出力する。同じ骨格・DNA・色・文字サイズで、
初回の1と指定値を左右に配置する。`same-dna-strokes.svg` も指定した度合いになる。
作品設定・manifest内の `inputs.stroke.intensity` に値を記録する。中間値2.5と最大値4の
三作品・全59文字、英字Iの交点、oの穴、数値の拒否、固定入力再現をテストする。

出力は3ポスター、各ポスターの中心線図、3列のまとめ、同一DNAのストローク例、
各作品の59文字分の独立SVG・出現箇所と配置・設定・出典。グリフSVGは共通1000座標の
閉じた塗りパスだけで、文字・フォント・外部参照を含まない。出力先は新規ディレクトリに
限定し、生成失敗時は途中結果を公開しない。

中心線の変化、ループ内側の保持、欠字拒否、全歌詞の出現対応・SVG検証・出典・失敗時の
原子性をテストする。字形の美しさ、歌い方に合う表情の選択は人が見て判断する。

## 曲へ載せるための現在地

`lyric-performance-1` は**実験用作品パッケージ**。既存bundle-v2を装わず、Kachincoや
KineticTypoでそのまま再生できる形式とは記述しない。各グリフSVGとポスターSVGは
フォントなしのベクター素材として使え、出現ID・行・列・配置をmanifestに保存する。

今回は曲・歌唱データがないのでcue時刻はnull。文字ごとの歌唱位置も推測しない。
音源ができた段階でSRT/配置と結び、配置・動き・再生はKineticTypo等のconsumer側で扱う。
ここではAI訓練・音楽生成・サービス・既存player契約の変更を行っていない。

全字対応ではなく、この歌詞に収録された骨格だけを対象にする。複雑な組版、正式な書道の
教師ラベル、物理的な毛筆再現ではない。これらの制約を理由に比較研究を増やすのではなく、
次は作品の感情や音に合うかを見て、必要なところを直す。
